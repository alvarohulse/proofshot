# How ProofShot Works

ProofShot is a thin orchestration layer between AI coding agents and a real browser. The agent calls ProofShot via shell commands. ProofShot manages sessions, logging, and artifact generation. All browser work is delegated to [agent-browser](https://github.com/vercel-labs/agent-browser).

## Architecture

```
┌──────────────┐     shell commands     ┌───────────────┐     CLI calls     ┌──────────────────┐
│  AI Coding   │ ────────────────────►  │   ProofShot   │ ──────────────►  │  agent-browser   │
│    Agent     │                        │     CLI       │                   │  (Rust + Node)   │
│              │  proofshot start       │               │  ab open ...     │                  │
│  Claude Code │  proofshot exec ...    │  session mgmt │  ab click ...    │  Chromium daemon │
│  Cursor      │  proofshot stop        │  video trim   │  ab screenshot   │  video recording │
│  Codex       │                        │  error detect │                   │  element refs    │
│  Gemini CLI  │                        │  artifact gen │                   │                  │
│  Windsurf    │                        │               │                   │                  │
└──────────────┘                        └───────────────┘                   └──────────────────┘
```

## Why agent-browser?

The choice of [agent-browser](https://github.com/vercel-labs/agent-browser) as the browser automation layer is the most important design decision in ProofShot.

**Agent-agnostic by design.** agent-browser exposes a CLI interface. Any AI agent that can run shell commands can drive it. This is what makes ProofShot work with every major coding agent without custom integrations.

**Persistent daemon.** agent-browser runs a Node.js daemon that maintains browser state across CLI calls. Sequential `proofshot exec` commands operate on the same browser tab and page state.

**Stable element references.** The `@eN` ref system provides stable handles to interactive elements. An agent takes a snapshot, sees `@e3: Submit button`, and can target it reliably — far more robust than CSS selectors for AI-driven interaction.

**Lightweight context.** Snapshot output is significantly smaller than alternatives, leaving more room in the agent's context window for reasoning.

**Built-in recording.** Playwright's screencast API is exposed directly, and ProofShot selects agent-browser's real-time H.264 MP4 encoding path during capture.

## Session lifecycle

ProofShot uses a three-phase model.

### Phase 1: Start

`proofshot start` initializes the session:

1. Check if the port is available (fail fast on conflicts)
2. Spawn an isolated dev-server process session if `--run` is provided, pipe timestamped output to `server.log`, and persist its immutable PID/process-group identity
3. Wait for the port to respond (polls every 500ms, 30s timeout)
4. Verify agent-browser 0.34.0, reject inherited provider/CDP/profile/state modes, and copy a safe config into private per-session state
5. Open the requested URL in a unique namespace with a target-domain allowlist and persist the daemon identity
6. Start private HAR capture and video recording
7. Register the immutable session ID and operation lease under the user state directory; write `metadata.json` beside the evidence

Recording is mandatory. If it fails after 3 retries, the session aborts.

### Phase 2: Exec (repeated)

Each `proofshot exec` call:

1. Selects the single addressable recording or requires `--session <id>` when several live sessions match
2. Claims an immutable exec lease
3. Captures pre-action page context and element data where available
4. Appends sanitized intent, interaction category, timing, and outcome to `session-log.json`; raw structured output stays private
5. Forwards the command to the exact agent-browser namespace and releases the lease

### Phase 3: Stop

`proofshot stop` collects and bundles everything:

1. Claims a stop lease and collects console evidence
2. Atomically finalizes private HAR evidence and writes a metadata-only network summary
3. Stops video recording and closes only the exact owned browser/environment/server processes
4. Trims dead time from the H.264 `session.mp4` using ffmpeg and adjusts action timestamps
5. Generates canonical evidence, verdict, summary, viewer, and provenance manifest
6. Unregisters completed ownership, or retains the exact browser record after `--no-close`

## Design principles

**Graceful degradation.** Missing ffmpeg? Video trimming is skipped, preserving the original `session.mp4`. Element data capture fails? Overlays are skipped. Browser already closed? The evidence is marked incomplete rather than overstated.

**Pinned browser contract.** ProofShot pins agent-browser 0.34.0 and fails before launch on older versions. Managed launchers keep its Node 24 runtime separate from project runtimes.

**Session isolation.** Registry-backed immutable IDs, namespaces, sockets, operation leases, and evidence directories allow concurrent sessions in one worktree without cross-session cleanup.

**Private evidence boundary.** Raw JSON, HAR, response bodies, credentials, and customer data remain in a user-only private directory excluded from manifests and publication.

**ESM-only.** All imports use explicit `.js` extensions for correct resolution after TypeScript compilation.
